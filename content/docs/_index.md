这一章不是泛泛的 Hugo 教程，而是这个仓库的说明书：每一页都对着一个真实存在的文件、一个真实生效的配置项，或者一条你会在终端里敲下的命令。读完一章，你应该能直接打开对应的文件把它改掉，而不是先去找教程。

## 这一章怎么组织

章节按依赖顺序排列：先让站点跑起来，再理解它由哪些部分构成，然后一层一层往下看。顺序是**起步**、**配置**、**内容**、**模板**、**资源**、**SEO**、**部署**、**代理**、**参考**。每一节的 `_index.md` 就是这一节的目录，左侧栏也按同一套顺序展开，所以侧栏的顺序和正文推荐的阅读顺序不会互相打架。

侧栏只展开你当前所在的那条路径，其余分支折叠着——一个有二十个章节的手册如果全部展开，得到的是一堵链接墙，比没有导航更难用。

## 阅读之前需要什么

你只需要三样东西：

- 一个 0.146 或更新的 Hugo 可执行文件。主题的 `hugo.toml` 在 `[module.hugoVersion]` 里声明了 `min = '0.146.0'`；低于它时 Hugo 只会打出一条 `Module "hugo-scratch-theme" is not compatible with this Hugo version` 的**警告**然后继续构建——所以本仓库的严格构建（`--panicOnWarning`）会把这条警告变成失败，而裸 `hugo` 不会提醒你。当前构建这个站点的版本是 {{< version >}}。
- 一份带子模块的仓库副本。主题 `themes/hugo-scratch-theme` 是以 git 子模块的形式挂进来的，普通克隆拿到的是一个空目录。
- 一个能改文本的编辑器，以及一次 `npm ci`。主题的设计系统与脚本都走 Hugo 自己的 `css.Build` / `js.Build`，不需要 Sass；只有 Tailwind v4 那一段调用 npm 装在站点根目录的 CLI。

如果你还没有本地的仓库副本，从[快速开始](/docs/start/quick-start/)开始；已经跑起来了就直接进入[目录结构](/docs/start/directory-structure/)，先弄清哪些目录能改、哪些是构建产物。

## 每页都带着"该不该读"的信息

文档页的 front matter 里除了标题和描述，还有四个字段：`difficulty`、`estimatedTime`、`prerequisites`、`outcomes`。它们不是装饰——`layouts/_partials/facts.html` 会把它们渲染成正文上方的信息面板，而 `pages.json` 这个输出格式把同样的值交给机器读。所以一个读者可以三秒钟判断"这页是不是给我看的"，一个代理可以不抓取整页就知道该不该照做。

{{< note >}}
本页提到的 `difficulty`、`estimatedTime` 等字段对所有文档页都适用，但**章节索引页**（`_index.md`）本身不需要填写——它只负责列出子页。
{{< /note >}}

## 页面之外还有什么

文档章节只覆盖这个仓库本身。想了解为什么这么设计、踩过哪些坑，去看[博客](/blog/)——那里的笔记是过程记录，不是参考手册。站点级的信息（许可证、隐私）在[法律声明](/legal/)里，版本变化在[更新日志](/changelog/)里。

当一个页面的正文和某个配置文件出现分歧时，以仓库里的文件为准：正文可能落后于一次提交，而构建出来的页面不会。
