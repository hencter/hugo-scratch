这一节只有两页，但它们是后面所有章节的前提：先把站点跑起来，再弄清楚你正在看的目录里哪些是源码、哪些是构建产物。跳过这一步直接去改模板，通常的结果是改了 `public/` 里的文件，然后被下一次构建覆盖掉。

## 这一节的两页

[快速开始](/docs/start/quick-start/)负责让站点在 `localhost` 上出现。它从 Hugo 的版本要求开始，然后处理这个仓库最容易踩的一步：主题是以 git 子模块挂进来的，所以克隆命令必须带 `--recurse-submodules`。用普通 `git clone` 拿到的 `themes/hugo-scratch-theme` 是一个空目录，Hugo 会以此为由拒绝渲染，而错误信息只说"找不到布局文件"，不会告诉你子模块没拉下来。

[目录结构](/docs/start/directory-structure/)给出整个仓库的目录树，并且逐行说明每个目录的用途。这一页里有一张"不要动"的清单——`public/`、`resources/`、`.hugo_build.lock`、`hugo_stats.json`，它们是构建的输出或状态文件，手改的结果要么被覆盖，要么让下一次构建读到自相矛盾的状态。

## 你需要什么

一个 0.146 或更新的 Hugo 可执行文件，这是主题在 `[module.hugoVersion]` 里写下的下限；一个带子模块的仓库副本；一个终端；以及一次 `npm ci`——Tailwind v4 的 CLI 装在站点根目录，只有样式表的那一段用到它。设计系统与脚本不需要 Sass 编译器：它们完全由 Hugo 的 `css.Build`、`js.Build` 处理，字体和图片都是静态文件。

Hugo 用 `hugo version` 自报家门，第一件事就是运行它。如果它打印的版本低于 0.146，先升级再往下走——低于下限时构建会在读取模块配置的阶段就失败，而不是在某个页面上报错，所以看起来会像是站点本身坏了。

## 跑起来之后先验证什么

`hugo server` 启动后，首页应该渲染出标题、导航栏和语言切换器；如果页面只有一堆没有样式的纯文本，多半是主题没被加载，而不是 CSS 丢了。再打开[快速开始](/docs/start/quick-start/)这一页本身，按 <kbd>Ctrl</kbd> + <kbd>C</kbd> 之前改一句话保存，看浏览器是否自动刷新——热重载是开发服务器的核心收益，如果它没生效，后面每一次改动都要手动重启，效率会差一个量级。

## 接下来去哪里

把站点跑顺之后，不要急着改模板。先读[配置](/docs/configuration/)——它解释了这个站点为什么不把 `hugo.toml` 放在根目录，以及主题、`_default`、环境配置三层的合并顺序。理解这一层之后，你在任何页面里看到的任何一个值，都能顺着配置文件找到它的出处；反过来，你会一直在猜某个参数是从哪来的。
