A search engine does not read your design; it reads the HTML the templates emit. This chapter is therefore not about writing technique but about what this site does at the template layer: which elements organise a page, how the structured data is generated, and which files exist purely to be discovered by machines. Together the three pages cover one crawl from finding a URL to understanding the text.

## The three pages in this section

[Semantic HTML](/docs/seo/semantic-html/) covers the most basic and most easily skipped layer: how `header`, `nav`, `main`, `aside` and `footer` divide the work, why a page carries exactly one `h1`, what the skip link and `aria-current` solve, and why a date is written as `<time datetime>` but displayed in Chinese.

[Structured data](/docs/seo/structured-data/) explains the single `@graph` produced by `layouts/_partials/head/schema.html`: what Organization, WebSite, the page node and BreadcrumbList each contribute, why piping the result of `jsonify` straight into `<script>` yields a string literal instead of JSON, and how to validate the output with Google's and schema.org's tools.

[Discovery](/docs/seo/discovery/) is a checklist: the generated `robots.txt`, the multilingual `sitemap.xml`, the Markdown twin of every page, `llms.txt`, `pages.json`, `search.json`, and site verification for Google and Bing.

## What one crawl uses, in order

Line up the three pages of this chapter in the order a crawl happens and they turn out to be links in a single chain:

1. A crawler reads `/robots.txt` first. It is generated by `layouts/robots.txt`, it only allows crawling in a production build, and its `Sitemap:` line gives the absolute address of the sitemap.
2. `/sitemap.xml` is an index on a bilingual site, pointing at one list per language; every URL in those lists carries `lastmod` and a set of `xhtml:link` hreflang entries.
3. When a page is actually fetched, the canonical URL in `<head>` says which address is the original, and hreflang plus `x-default` say which language variants exist.
4. The body is read by landmark: `main` is the text, `aside` is supplementary, and heading levels descend from the single `h1` without skipping.
5. The JSON-LD in the same `<head>` supplies publisher, site, page type and breadcrumbs, so a machine never has to guess them.
6. A client that would rather not parse HTML takes the other road: append `index.md` to the URL for the Markdown twin, or read `/pages.json`, `/search.json` and `/llms.txt` directly.

Only step 4 has anything to do with writing. The rest lives in templates — which is why this chapter is about templates rather than about writing technique.

## Why this is a template concern, not a content concern

None of the items above can be obtained by writing better prose. A canonical URL must be absolute, translation links require iterating over the translations, and a breadcrumb trail has to agree with the visible navigation — all of it belongs to the templates under `layouts/_partials/head/`, and an author neither should nor can intervene.

That brings a benefit: fix it once and the whole site has it. Add one field to `head/meta.html` and hundreds of pages gain it at the same moment. The reverse also holds — a mistake in a template appears on every page simultaneously — which is why this chapter stresses verification rather than memorising field names.

## Only a production build is index, follow

The robots directive in `head/meta.html` depends on the build environment. By default it is `index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1`; anything that is not a production build becomes `noindex, nofollow` wholesale. The test is `hugo.IsProduction`, and a **plain `hugo` command *is* the production environment** — only `hugo server` or an explicit `hugo -e development` is not.

{{< warning >}}
The most common preview-deployment mistake is forgetting to add a noindex header. Here the default is inverted: no head at all unless it is production. If you inspect the source of a page under `hugo server` and find `noindex`, that is the design working, not a broken configuration — `layouts/robots.txt` switches on the same condition and returns `Disallow: /` outside production.
{{< /warning >}}

A single page can override both decisions from front matter: `robots` takes the directive string directly, and `noindex = true` forces the page out of the index.

## How to check it yourself

A one-shot inspection beats memorising field names:

```bash
hugo --ignoreCache
cat public/robots.txt
grep -o 'rel="canonical"\|hreflang="[^"]*"\|application/ld+json' public/docs/assets/css/index.html
```

The first command confirms that the `Sitemap:` line in `robots.txt` is absolute; the second confirms that any page's head carries a canonical URL, paired hreflang links and a JSON-LD block. Then open `public/sitemap.xml`: with more than one language it is a `<sitemapindex>` and each language has a sitemap of its own. When all three check out, what remains is the content itself.
