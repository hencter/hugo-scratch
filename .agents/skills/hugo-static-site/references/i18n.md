# Internationalization (optional)

**This module is opt-in.** A single-language site needs none of it — it only needs `locale` so
dates, numbers and percentages format correctly (`dates.md`). Add multilingual support when the
site must serve more than one language, or when UI strings should be translatable independently of
content.

## Decide the structure first

**Translation by file name** (the default): one content tree, one file per language, linked by path
and base name.

```text
content/
├── _index.md          content/_index.zh.md
├── _index.en.md
└── about/
    ├── _index.md      content/about/_index.zh.md
    └── about.en.md
```

**Translation by content directory**: one directory per language, and `contentDir` per language.
Omit `contentDir` when translating by file name.

```toml
[languages.de]
contentDir = 'content/de'
[languages.en]
contentDir = 'content/en'
```

## Configuration

```toml
defaultContentLanguage = 'zh-cn'
defaultContentLanguageInSubdir = false   # true → publish the default language under /zh-cn/
disableLanguages = []                    # prefer `disabled = true` per language

[languages.zh-cn]
label = '简体中文'        # 0.158+: languageName → label
locale = 'zh-CN'          # 0.158+: languageCode → locale
direction = 'ltr'         # 0.158+: languageDirection → direction
title = '项目文档'
weight = 1
[languages.zh-cn.params]
subtitle = '参考、教程与说明'
```

- Language keys follow RFC 5646 (`de`, `en-US`, `pt-BR`). Artificial languages drop the `art-x-`
  prefix and are limited to 8 characters (`hugolang`).
- Languages sort by `weight` ascending, then lexicographically; that order drives build order.
- Any key omitted under a language falls back to the project-level value. Only *some* keys can be
  set per language (`title`, `locale`, `direction`, `params`, `pagination`, `timeZone`, …) — check
  the generated list with `hugo config --lang <key>`.
- Multihost: give every language its own `baseURL`. If one language defines it, all must.

## Linking translations

- Same path + base name within each language's content directory → linked as translations.
- A file with no language code belongs to the default language.
- `translationKey = "about"` in front matter links pages regardless of name or location — use it
  when the translated file cannot keep the same basename.
- Translated pages share the same URL apart from the language subdirectory.
- A page bundle inherits the resources of its linked translations' bundles (content files
  excluded), so images do not need duplicating.

## Templates

| Need | Use |
| --- | --- |
| Other translations of this page | `.Translations` |
| Every translation including this one | `.AllTranslations` |
| Is this page translated at all? | `.IsTranslated` |
| Current language key / label / direction | `.Lang`, `.Language.Label`, `.Language.Direction` |
| Language switcher | loop `site.Home.AllTranslations` and link `.RelPermalink`, label from `.Language.Label` |

```go-html-template
<html lang="{{ site.Language.Locale }}" dir="{{ site.Language.Direction }}">
{{ with .AllTranslations }}{{ if gt (len .) 1 }}
<nav class="lang-switch">
  {{ range . }}<a href="{{ .RelPermalink }}" hreflang="{{ .Language.Locale }}"
    {{ if eq .Lang $.Lang }}aria-current="true"{{ end }}>{{ .Language.Label }}</a>{{ end }}
</nav>
{{ end }}{{ end }}
```

Set `dir` from `.Language.Direction` — it is the documented way to support right-to-left languages.

## UI strings

`i18n/<language-key>.toml`:

```toml
[readMore]
other = '继续阅读'

[itemCount]
one = '{{ .Count }} 项'
other = '{{ .Count }} 项'
```

- Read them with `T` (alias `i18n`): `{{ T "readMore" }}`, `{{ T "itemCount" 12 }}` for the plural
  form, `{{ T "key" (dict "count" 12 "name" "x") }}` to pass context.
- Missing translation → the default language's value → an empty string. A missing key is silent
  unless you ask: `enableMissingTranslationPlaceholders = true` renders `[i18n] identifier`, and
  `hugo --printI18nWarnings` lists them at build time.
- Menu entries can be translated through the same table, keyed by the entry's `identifier`,
  falling back to `name`.

## SEO and dates across languages

- Emit `hreflang` alternates only when there is more than one language — see `seo.md`.
- Hugo publishes a sitemap and RSS feed per language; `defaultContentLanguageInSubdir` decides
  whether the default language lives at `/` or `/<lang>/`.
- Formatting is per language: `locale` drives dates and numbers, and the localized `:date_*` tokens
  are incomplete for some languages (`zh-CN` falls back to English — see G22 in `gotchas.md`).
  Define `dateFormat` in each language's `params` instead of trusting the token.

## Verify

```bash
hugo --printI18nWarnings          # missing translations, per language
hugo config --lang en             # the effective configuration for one language
hugo list all                     # every page, across languages
```

The build output prints a matrix of the languages it built; compare it with the ones you expect.
Check one page per language in `public/<lang>/…`, and check that the switcher links to real
`index.html` files rather than 404s.

## Pitfalls

- Filenames must match **including the base name**: `about.en.md` and `about.zh.md` pair;
  `about.en.md` and `guanyu.zh.md` do not — use `translationKey` instead.
- Adding `contentDir` while still translating by file name splits the content tree and the
  translations silently stop pairing.
- `.Translations` is empty when pages are not linked; that is a linking problem, not a template one.
- Renaming a translated file changes its URL in that language only; re-check inbound links.
